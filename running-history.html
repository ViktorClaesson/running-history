Each lap scores its speed (km/h) to the power below, times its distance, towards the zone it was run in. Then, hardest first, each zone is pooled with every faster one, and the first pool to reach the share below is the run’s type — so hard work split across interval and repetition still adds up to an interval session, and a few strides don’t turn an easy run into a repetition one. Zones are the pace-zone histogram’s own, against that day’s VDOT.

Pace-zone volume

Zones standing walking recovery endurance marathon threshold interval repetition One rolling window’s running, split by which pace zone the kilometres were actually run in — so the bands add up to that window’s own distance-per-week line, the one drawn in that colour further up. Slowest band at the bottom, so the hard running is the band on top — the same order the pace-zone histogram reads left to right. Whole zones only, never the histogram’s sub-bands: “how much threshold have I been running” is not a question about threshold 2. Zones come from each day’s own VDOT, so a run the export has no recorded time for puts nothing in the stack, which is the one way a total can end up under that line.

Running history — every run, on a log scale

One bar per day, height is that day’s own distance on a logarithmic axis — 5→10 km is the same step as 10→20, so one very long run can’t flatten every short one and short runs stay readable against each other. A day with no run gets a tiny grey stub below the axis floor rather than nothing at all, which also keeps it easy to hover and click. The colour is not about that one run: it says which rolling distance-per-week window is highest that day — the shortest one winning is the strongest reading — so the answer is “is my training trending up” rather than “was this run long enough”. Rolling weekly volume has moved to its own panel just below, in the same four colours.
